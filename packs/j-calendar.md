# J · 日历检查、空档、最少入住晚数、换房清洁排班表（精简）

每天或每周。运行脚本后汇报；绝不手动数日期。

## 运行
用户上传一个或多个文件：Airbnb 日历导出（.ics —— Listing → Availability → sync/export calendar；把链接下载成文件）、Airbnb 预订 CSV（Reservations → Export），和 / 或其他渠道的 .ics。
`python3 scripts/calendar_check.py <files> --property "<listing name>" [--as-of YYYY-MM-DD] --min-stay <card or 2> --occ-target <settings, default 60> --out <CODE>`
如果对话日期和系统时钟不同，使用 `--as-of`。

## 回复用户（简短；用用户的语言（settings.md 里设置，默认中文））
1. 先列脚本的**警告**，每条一行（重叠 / 可能重复预订、同一天换房时间过短）。
2. 30 / 60 / 90 天入住率，以及未来 7–14 天的换房清洁清单（从输出中复制）。
3. 最后列脚本的**提示**（最多 3 条），用提问的方式。除非用户说“好”，否则不再做其他事。

## 如果确实存在重复预订 / 重叠
处理顺序：保留先确认的那个预订 → 如果需要换房，免费提供同等或更好的房子 → 取消只作为最后手段，并全额退款（房东取消可能会被 Airbnb 处罚 —— 取消前先查看当前的 Help Center 页面）。用 `msgs/guest-5-changes.md`（F4）起草给客人的消息。立即在另一个渠道上屏蔽这些日期。

## 如果用户同意处理某个空档提示（不需要额外文件）
| 空档 | 操作 |
|---|---|
| 短于最少入住晚数 | 仅对这几天把最少入住晚数降到空档长度 |
| 14 天以内 | 这几晚定价为正常价的 85–90% |
| 7 天以内 | 正常价的 75–85%；清洁完成后允许当天预订 |
| 紧挨着已有的入住 | 向那位客人提供续住（`msgs/guest-3-stay.md` D7） |
| 工作日单晚，清洁成本接近房价 | 考虑空着；列出算式（房价 − 清洁 − Airbnb 费用） |
| 节假日 / 活动当晚 | 不打折；只降低最少入住晚数 |
如需完整的定价方案，用户可以说“做定价” → `packs/k-pricing-weekly.md`。

## 换房清洁排班表 / 清洁工排班
`<CODE>_board.json` → `python3 scripts/render.py <CODE>_board.json board.html`（先在最后一列填上清洁工名字）。给清洁工的消息：`msgs/vendor.md` CL1–CL3（仅在用户需要这些消息时才读取）。

## 渠道健康度（当用户粘贴自己的 Airbnb 表现数据时）
标记：回复率 < 95%、回复时间 > 1 小时、接受率 < 85%（request-to-book（需申请预订））、任何一次房东取消、总评分低于 4.8、日历 30 天未更新。每个标记给一个改进办法。
