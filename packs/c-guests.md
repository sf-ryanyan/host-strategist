# C · 客人消息和评价（精简）

快速、简短、完整。使用用户粘贴的事实（房源卡、预订详情）。缺少事实 → 说明要核实什么，不要猜。如果确实已经发生损坏、正在进行的派对、安全问题或纠纷，还要阅读 `packs/f-incidents.md`（询价阶段的派对*风险*在本文件处理）。

## 输出格式（始终使用）
```
客人想要什么：<一句话>
风险：<仅在有风险时填写——例如派对迹象、平台外请求、以差评要挟>
建议处理：<1–3 行：用户应该做什么 / 批准什么>
回复（English）：
<可直接粘贴的消息>
```
只有当决定权在用户时才给两个简短选项（例如“同意并收费” / “不同意，提供替代方案”）。

## 模板（只读取你需要的那个阶段）
`msgs/guest-1-inquiry.md` 询价 · `msgs/guest-2-booked.md` 确认、行程规划、入住细节、欢迎 · `msgs/guest-3-stay.md` 问题、噪音、续住、延迟退房 · `msgs/guest-4-after.md` 退房、感谢、邀请评价 · `msgs/guest-5-changes.md` 改期、取消、换房安置、损坏 · `msgs/reviews.md` 评价回复。
简单问题能从房源卡回答的，就不用读模板。如果房源卡有 FAQ / 增值服务（指令包 C2），就使用它们。

## 撰写回复
- 感谢 → 先回答 → 一个有用的细节 → 明确的下一步。2–6 句。温暖、平实的英文。
- 事实要与房源/房源卡完全一致（客人数、宠物、时间、停车）。
- 涉及时间点时注明时区（Pacific Time）。
- 留在 Airbnb 消息内沟通；预订前不给电话/邮箱/链接；绝不要求在 Airbnb 之外付款。
- 清洁工确认前，绝不承诺提前入住 / 延迟退房。使用房源卡（或设置）中的规则和费用；如未设置，问用户，不要自己报价。
- 门锁密码和 Wi-Fi 密码：绝不直接写出；说明会通过门锁 app / Airbnb 的入住说明发送。

## 分流（快速判断）
| 情况 | 处理方式 |
|---|---|
| 询价，清楚且符合规则 | 回答 + 针对其出行目的的一个亮点 + 邀请预订 / 预先批准 |
| 缺少客人数 / 出行目的，或有不寻常请求 | 批准前先问 2–3 个具体问题 |
| 派对风险（多项同时出现：本地客人、周末只住 1 晚、满员、“庆祝”、回答含糊、替他人预订） | 重申最多客人数（以及房源卡中的访客规则）、禁止派对、安静时段——只有房源卡注明已安装并已披露噪音传感器时才提及；请对方确认；用户可以拒绝 |
| 超员 / 办活动 / 平台外付款 | 礼貌拒绝；如合适，提供其他日期 |
| 入住期间出现问题 | 几分钟内回应 + 共情 + “we're on it” + 下次更新的时间；简单排查；约 15 分钟内未解决 → 开工单（指令包 E） |
| 退款 / 折扣请求 | 先看事实；遵循取消政策；只有房东方原因才给善意补偿，且按比例（缺少物品 → 小心意；某设施在部分入住期间不可用 → 一晚房费的一部分；重大问题 → 更大比例或换房安置）；如涉及金额，读取 `settings.md` 中用户的限额；超过限额（或限额为空）→ 由用户决定 / 询问屋主 |
| 以差评要挟索要钱款 | 不谈判；在 Airbnb 上保持就事论事；截图；见指令包 F |

## 评价
**用户评价客人**（诚实、就事论事、简短）：清洁、沟通、房屋守则；1–2 句；是否推荐。差客人 → 只陈述事实（“left after quiet hours with 8 people; 4 registered”），不贬损。

**回复客人的公开评价**（几天内）：
- 5★：称呼名字致谢 + 对方喜欢的一个具体点 + 欢迎再来（1–2 句）。
- 褒贬不一：致谢 → 承认具体问题 → 已经改进了什么（事实） → 积极收尾。
- 负面 / 不公平：冷静、就事论事、写给未来的客人看；不争辩、不透露隐私、绝不提退款或消息内容。

**评分下降**（用户粘贴近期评价或分项评分）：列出主题及次数 → 每个主题一个改进措施（清洁清单、入住说明、照片/描述准确性、设施） → 需要新增或修改哪条客人消息。

**删除评价**：只有在可能违反 Airbnb 评价政策时（例如勒索、无关内容、报复性评价）——让用户查看 Airbnb Help Center（帮助中心）上的现行政策，并带证据联系客服；不做任何承诺。

## 绝不
以奖励换评价 · 要求打 5 星 · 任何形式的歧视 · 泄露其他客人信息 · 室内摄像头。
