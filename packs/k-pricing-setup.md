# K2 · 定价设置、活动更新、竞品更新、定价工具（定期 / 深度）

只读取用户要求的那一节。每节的联网额度在下面固定写明；超出前先询问。

## §Setup 定价规则设置（深度，每个房源一次）—— 生成 `pricing_<CODE>.json`
1. 从 `python3 scripts/rate_plan.py --example > pricing_<CODE>.json` 开始。
2. 工作日 / 周末基础价 = 竞品中位数 × 质量调整（评价 / 照片 / 设施更好 → +5–15%；更弱 → −5–15%）。竞品数据来自指令包 A、最近一次竞品更新，或用户的 AirDNA / PriceLabs 数据。
3. 底价 = max( (清洁成本 + 耗材) ÷ 平均入住晚数 + 每晚水电费, 再加最低屋主利润 ) ÷ (1 − Airbnb 费用) ÷ (1 − 管理费) —— 列出算式；长期间段也不能低于长租月租 ÷ 30。上限 ≈ 基础价的 2.5–3 倍。
4. 季节系数：如果用户有去年自己的数据，就用它；否则用市场数据；说明用的是哪一种。
5. 最少入住晚数矩阵：工作日 / 周末 / 7 天以内 / 节假日（默认值见示例；按竞品调整）。
6. 把文件交给用户，并提醒用户自己保存；每周检查会重复使用它。

## §Events 本地活动更新（每月，联网额度 ≤ 5 次搜索）
查找房源附近未来 90 天的大型需求来源：会展中心、体育场 / 体育馆、大学重大活动（毕业典礼）、大型科技会议、节庆活动。**只用主办方 / 场馆官方页面；记录来源 + 查看日期。** 写入 `events.csv` 行：start,end,name,uplift_pct（按规模 10–50）,min_stay,source,verified_on。未核实的 → 不写入，列为“需核实”。

## §Comp refresh 竞品更新（每季度，≤ 8 个竞品，联网额度 ≤ 8 次抓取，或用用户粘贴的数据）
相同卧室 / 卫生间 / 可住人数，约 1–2 英里范围内；记录 2–4 周后一个工作日和一个周末的价格、评分 / 评价数、清洁费、最少入住晚数、观察日期。输出：工作日和周末的 P25 / 中位数 / P75、本房源所处位置，以及建议的基础价调整（pricing.json diff）。

## §Pricing tools 定价工具（深度建议，在官网核对当前价格）
按用户的房源数量做对比：Airbnb 自带的 Smart Pricing（智能定价；免费；控制少，容易定价偏低）vs 专业工具（PriceLabs、Wheelhouse、Beyond —— 按房源收费；有最低 / 最高价、孤立空档日（orphan-day）和活动规则、市场看板）。根据房源数量、用户可投入的时间和对控制权的需求来推荐。价格只引用今天查看过的厂商页面。

## §Settings review 工具设置复核（已在使用某个工具时）
表格：设置项 · 当前 · 建议 · 理由 —— base、min、max、seasonality、day-of-week、last-minute、far-out、orphan-day、按提前天数的最少入住晚数、入住率调整、同步到 Airbnb。
